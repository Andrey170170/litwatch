# GLM high and targeted recall evaluation — 2026-09-09

## Decision and hypothesis

Replace the OpenRouter Sol-low recall stage with `z-ai/glm-5.3` at **high** effort.
Rejudge only the selections whose primary verdict is low confidence or whose tier 4
has an eligible keyword hit. Ignore the exact case-insensitive pattern `benchmark`
for escalation only. Preserve authored keywords, selection versions, ingestion
matching, all-topic low-confidence checks, and Muse confirmation of every remaining
primary or secondary tier 1/2 judgment. Cap secondary completion tokens at 8192,
including reasoning. No production papers are re-screened for this rollout.

The hypothesis is that topic-scoped calls and fewer generic keyword escalations
reduce recurring cost while retaining useful recall corrections. This is a pipeline
comparison: changing both model and scope does not isolate GLM's quality from the
trigger change, and it does not establish superiority to Luna or Sol.

GLM's published supported reasoning efforts are low/high/max; high meets the user's
medium-or-high preference: https://openrouter.ai/z-ai/glm-5.3 . Provider routing can
change actual costs. Deep processing still uses Sol through the Codex subscription;
that is separate from OpenRouter spend.

## Frozen inputs and procedure

- Run 11: 677 newly ingested papers, six active selection specs, frozen primary
  Luna decisions and recorded Sol/Muse decisions. Read-only production export;
  no database credentials were mounted into evaluation containers.
- Old policy: 233 paper-level recall calls judging 1398 paper/selection pairs.
  New policy: 140 calls judging 148 pairs (40% fewer calls, 89% fewer topic judgments).
- Replay all 140 new-policy calls with GLM high, plus all 12 CoT tier-1 reference
  entries from `evals/labeled.yaml`. References mix human and machine-assisted labels
  and predate the current rubric; they are positive controls, not an unbiased test set.
- Reuse recorded Muse confirmations when available: its prompt depends only on the
  paper and selection, not the previous model's verdict. Run missing confirmations
  separately. Retaining primary positives creates some new confirmation calls that
  the old full-scope Sol pass had suppressed by demoting those positives.
- Paid requests: no SDK automatic retries, 120-second request timeout, 8192 completion
  tokens, four concurrent replay calls. Initial 24-call segment had a $3 stop threshold;
  remaining disjoint 128-call segment had a $2 threshold. These thresholds stop new
  work based on reported cost with $0.05 reserved per in-flight capped request; they
  are not an account-level spending limit. Follow-up checks were individually bounded.
- The initial replay supplied an explicit JSON schema. Two canaries and the malformed
  response retry exercised `ModelScreener.screen` and the production SDK strict-parser
  path directly. The committed replay helper now uses the SDK's strict schema too.

## Results

- 151/152 initial GLM calls returned valid structured verdicts. One replay on
  `2609.07409` (Modal provider) emitted malformed repetitive JSON and hit 8192 tokens,
  costing $0.037253. A bounded retry through the production parser succeeded, tier 4,
  for $0.0015338. Both charges are included in recall-stage cost below. The maximum
  successful initial completion was 4379 tokens. Production retains the existing
  pending-paper retry behavior on model failure; the cap is not a silent fallback.
- GLM assigned tier 1 to 11/12 CoT controls. It assigned `2307.13702` tier 2 because
  intervention-based importance proxies are explicitly tier 2 under the current
  rubric. Its historical tier-1 label has not been changed; human reconciliation
  remains necessary. This is not reported as a perfect recall score.
- Exact production-parser canaries preserved today's new CoT tier 1 (`2609.06704`)
  and the distillation tier-2 recovery (`2609.08337`).
- The narrower scope loses an incidental old Sol recovery: `2609.08637` changes
  alignment-and-safety from tier 2 to primary tier 3. Its escalation was triggered
  by efficiency, not alignment. This is the explicit trade-off of scoped rejudgment.

After all 27 missing Muse confirmations, no new-feed tier-1 assignments change.
There are two tier-2 additions relative to the recorded final verdicts: `2609.07741`
(alignment; an untouched primary positive that Sol had demoted) and `2609.08341`
(efficiency; GLM recovers TV-Regulated OPD from primary tier 4, then Muse confirms).
The one tier-2 loss is `2609.08637` above. These are verdict differences, not
human-validated accuracy gains. All other tier-1/2 assignments agree.

model rates alone would not reproduce these costs.

## Reproduction and limits

Implementation: release `v0.8.2`, commit `cbe2aea`.
`73` tests passed, including disposable PostgreSQL integration tests; Ruff passed.
The test suite covers partial output merging, confirmation of untouched positives,
keyword exclusions without authored-spec mutation, low-confidence routing, and
reasoning/token-cap request forwarding.

Durable raw snapshot, journals, canaries, confirmation outputs, and analysis helper:
`/srv/appdata/litwatch/evals/20260909-glm-high/`. These contain public-paper metadata
and frozen model decisions, not API credentials. The snapshot hash is recorded
alongside the artifacts. To rerun against the frozen inputs (incurs API charges):

```sh
PYTHONPATH=src python scripts/eval_rescreen.py SNAPSHOT.json NEW_RESULTS.jsonl \
  --labels evals/labeled.yaml --budget 1 --concurrency 4
```

The helper resumes recorded cases and refuses to proceed past unknown reported
charges. Failed-but-accounted cases are retained, not silently retried. Final verdict
comparison uses fixed Luna judgments and mostly reused Muse outputs; it does not
measure fresh full-cascade stochastic variation. New papers lack independent human
labels, and the positive controls cannot estimate false-positive rate. Tomorrow's
feed volume, provider routing, rubric edits, retries, and digest length can change
spend; the daily projection is not a hard budget. Digest cost is held at today's
regenerated pair for comparison, not re-generated for each candidate result.
